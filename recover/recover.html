Recover a Bitcard

Your two word-halves contain everything needed to reconstruct the Bitcard key without Bitcard, its app, or its website. Preserve this page, the open specification and the tested recovery tools with the card.

Read this first. A Bitcard uses two sets of 12 words, Part 1 (under the scratch/seal on the card) and Part 2 (written on the card). These are NOT a normal wallet seed. Typed into an ordinary wallet app they will show an empty, wrong wallet. You must combine both halves the Bitcard way (below) to get the real key. If a wallet shows nothing, the card is not empty, you are using the wrong method.

What you need

Part 1, 12 words hidden under the scratch panel on the card (peel it).
Part 2, 12 words handwritten on the card by the buyer.

You need both to spend. Part 1 alone cannot compute the address. Part 2 can compute the address and view its public balance only when combined with the public P1 from the card's QR; it still cannot spend.

Three ways to recover, easiest first

1. The Bitcard claim app (easiest while available). Open the genuine claim app, enter both halves, and it sweeps the coins to a wallet you choose. The saved app is self-contained, but claiming still needs network access to find and broadcast the bitcoin transaction.

2. The offline script (no app, no website). With Python 3.7 or newer, run bitcard-recover.py (kept alongside this page). It uses only the Python standard library, no package installs, validates your words, and prints the address and private key (WIF). Always run its self-test on the exact interpreter first:

python bitcard-recover.py --selftest        # confirms the tool is correct
python bitcard-recover.py                    # then paste each half when prompted (mainnet by default; add --testnet for a tb1 card)

Take the printed WIF and use your wallet's Sweep feature, not "Import". In Sparrow, select P2WPKH / Native SegWit as the source type. In Electrum, enter p2wpkh: immediately before the WIF in Wallet > Private Keys > Sweep. Before confirming, the wallet's source address must exactly equal the funding address printed by this tool. Keep both halves until the sweep confirms and that address shows zero balance.

3. From scratch (if even the script is gone). A programmer can reproduce the key from the frozen algorithm and test vectors below. This is why Bitcard infrastructure is not required, provided the words and recovery materials remain available and usable.

The algorithm (bitcard-claim-spec v0.4)

curve      = secp256k1  (order n)
for each half (Part 1, Part 2):
    seed   = PBKDF2-HMAC-SHA512(words, salt="mnemonic", 2048 rounds)   # BIP39, empty passphrase
    I      = HMAC-SHA512(key="Bitcoin seed", seed)                     # BIP32 master
    d_i    = int(I[0:32])  mod-check: reject if 0 or >= n
combined d = (d1 + d2)  mod n
address    = P2WPKH( compressed( d * G ) )     # bech32 hrp: "bc" mainnet, "tb" testnet

The card record byte (mainnet vs testnet) is public and on the card; everything else above is standard BIP39 / secp256k1.

Verify any tool with the frozen test vector

A correct implementation must turn these two halves into exactly this address. If your tool does, trust it with your real words:

Part 1:  abandon abandon abandon abandon abandon abandon abandon abandon abandon abandon abandon about
Part 2:  legal winner thank year wave sausage worth useful legal winner thank yellow
=>  address (testnet):  tb1q6h6zqgr7pzgf4e2j86f2v4m60r5p0wqrxddllm
    private key (hex):  968eaeb422670fce07c620c22d7d41204ef45a104cb8e4a7e64e41791ad135b5

This is one copy of an open standard; it does not need to stay online to work. Preserve redundant, hash-verified copies of this page, the specification, vectors and bitcard-recover.py in public repositories and content-addressed storage. Recovery does not require a Bitcard service, but it does require the words, these method details and compatible software. Bitcard never holds your keys or your coins.
