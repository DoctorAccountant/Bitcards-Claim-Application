Recover a Bitcard

Your bitcoin is recoverable with standard tools forever — even if Bitcard, its app, and this website no longer exist. This page tells you how, and lets you verify any tool you use.

Read this first. A Bitcard uses two sets of 12 words — Part 1 (under the scratch/seal on the card) and Part 2 (written on the card). These are NOT a normal wallet seed. Typed into an ordinary wallet app they will show an empty, wrong wallet. You must combine both halves the Bitcard way (below) to get the real key. If a wallet shows nothing, the card is not empty — you are using the wrong method.

What you need

Part 1 — 12 words hidden under the scratch panel on the card (peel it).
Part 2 — 12 words handwritten on the card by the buyer.

You need both. Either half alone cannot spend, reveal the balance, or even compute the address.

Three ways to recover — easiest first

1. The Bitcard app (easiest). Open the claim app, enter both halves, and it sweeps the coins to a wallet you choose. The app is open-source and runs offline. If it is still online, this is all you need.

2. The offline script (no app, no website). Run bitcard-recover.py (kept alongside this page). It uses only the Python standard library — no installs — validates your words, and prints the address and the private key (WIF):

python bitcard-recover.py --selftest        # confirms the tool is correct
python bitcard-recover.py                    # then paste each half when prompted (mainnet by default; add --testnet for a tb1 card)

Take the printed WIF and use your wallet's Sweep feature (Electrum/Sparrow: "Sweep"), not "Import", so the coins move to a fresh key you control. A Bitcard key is a one-time bearer key: do not keep or reuse it.

3. From scratch (if even the script is gone). Any programmer can reproduce the key from the algorithm below with any Bitcoin library. This is why the coins can never be locked away by us disappearing.

The algorithm (bitcard-claim-spec v0.3)

curve      = secp256k1  (order n)
for each half (Part 1, Part 2):
    seed   = PBKDF2-HMAC-SHA512(words, salt="mnemonic", 2048 rounds)   # BIP39, empty passphrase
    I      = HMAC-SHA512(key="Bitcoin seed", seed)                     # BIP32 master
    d_i    = int(I[0:32])  mod-check: reject if 0 or >= n
combined d = (d1 + d2)  mod n
address    = P2WPKH( compressed( d * G ) )     # bech32 hrp: "bc" mainnet, "tb" testnet

The card record byte (mainnet vs testnet) is public and on the card; everything else above is standard BIP39 / secp256k1.

Verify any tool with the frozen test vector

A correct implementation must turn these two halves into exactly this address. If your tool does, trust it with your real words:

Part 1:  abandon abandon abandon abandon abandon abandon abandon abandon abandon abandon abandon about
Part 2:  legal winner thank year wave sausage worth useful legal winner thank yellow
=>  address (testnet):  tb1q6h6zqgr7pzgf4e2j86f2v4m60r5p0wqrxddllm
    private key (hex):  968eaeb422670fce07c620c22d7d41204ef45a104cb8e4a7e64e41791ad135b5

This is one copy of an open standard — it does not need to stay online to work. The method above, the spec (bitcard-claim-spec.md), the frozen vectors (bitcard-test-vectors.json), and bitcard-recover.py are open-source and mirrored (public code repositories + content-addressed storage such as IPFS / Arweave), so recovery survives without any single website, domain, or company — including us. Recovery needs only your words, the method above, and any Bitcoin tool; nothing on your card depends on a site we keep alive. Bitcard never holds your keys or your coins.
